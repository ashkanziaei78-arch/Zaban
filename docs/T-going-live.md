# T. بالا آوردن سایت — راهنمای عملی

> این سند فرض می‌کند هاست خریده‌اید و می‌خواهید همین امروز سایت بالا بیاید.
> سند S معماری کامل را توضیح می‌دهد؛ این یکی فقط دستورالعمل است.

---

## T.0 اول این را بدانید

پروژه روی **سه دامنهٔ جدا** بالا می‌آید، و بستهٔ ساخت هم سه تا است —
سومی، پنل سوپرادمین، سند جداگانهٔ خودش را دارد
([V](V-super-admin.md))؛ اینجا فقط سایت و پنل آموزشگاه‌ها را
قدم‌به‌قدم می‌بریم بالا:

| بسته | چه چیزی دارد | کجا می‌رود | چه می‌خواهد |
|---|---|---|---|
| `dist/site/` | سایت معرفی | `httpdocs` دامنهٔ `talkora.ir` | فقط فایل ایستا |
| `dist/panel/` | پنل + `api/` | `httpdocs` زیردامنهٔ `panel.talkora.ir` | PHP ۸، MySQL، اکستنشن curl |
| `dist/admin/` | پنل سوپرادمین + `api/` | `httpdocs` زیردامنهٔ `admin.talkora.ir` | PHP ۸، همان دیتابیس پنل |

**چرا جدا؟** سه دلیل عملی، نه سلیقه:

1. کوکی نشست فقط روی `panel.talkora.ir` ست می‌شود. صفحهٔ فروش که همه
   می‌بینند، هیچ‌وقت کوکی احراز هویت حمل نمی‌کند.
2. سایت معرفی به دیتابیس دست نمی‌زند. اگر پنل خطای ۵۰۰ بدهد یا دیتابیس
   پر شود، صفحهٔ فروش‌تان همچنان بالاست.
3. سیاست امنیتی هرکدام فرق دارد: پنل `X-Frame-Options: DENY` و
   `noindex` می‌گیرد، سایت نمی‌گیرد.

بسته‌ها را بسازید:

```bash
python3 build-dist.py
```

خروجی: `talkora-site.zip`، `talkora-panel.zip`، و `talkora-admin.zip`.
هر بسته راهنمای فارسی خودش را داخل خودش دارد (`راهنمای-آپلود.txt`،
`راهنمای-پنل.txt`، `راهنمای-سوپرادمین.txt`). این سند فقط دو تای اول
را می‌برد بالا؛ سومی سند [V](V-super-admin.md) است — بعد از پنل نصبش کنید.

### احراز هویت واقعی کجا اجرا می‌شود

بک‌اند احراز هویت (`panel/api/`) عمداً **بدون فریم‌ورک و بدون composer**
با PHP و MySQL نوشته شده، دقیقاً تا روی همین هاست اشتراکی پلسک اجرا شود.
ورود با کد یک‌بارمصرف و پیامک sms.ir از همان روز اول کار می‌کند و سرور
مجازی نمی‌خواهد.

آنچه هنوز سرور مجازی می‌خواهد، بخش‌های سنگین است: `server/` (پستگرس با
جداسازی سطر به سطر مستأجرها)، کارگر ضبط کلاس، و خود BigBlueButton.
تا آن روز، پنل روی هاست اشتراکی ورود واقعی دارد و بقیهٔ صفحه‌ها با دادهٔ
نمونه کار می‌کنند.

### پنل خودش می‌فهمد در کدام حالت است

موقع بالا آمدن، پنل یک درخواست به `api/health.php` می‌زند:

- پاسخ سالم و `database: true` → **حالت واقعی**. ورود با پیامک، نشست
  واقعی، نقش از سرور می‌آید و نوار «نسخهٔ نمایشی» دیده نمی‌شود.
- بی‌پاسخ، خطا، یا دیتابیس پایین → **حالت نمایشی**. همان نمونهٔ تعاملی
  با دادهٔ ساختگی و کلید تعویض نقش.

یعنی اگر بعد از آپلود نوار «نسخهٔ نمایشی» را دیدید، پیام روشنی است:
`api/health.php` جواب نداده. اول همان را در مرورگر باز کنید.

## T.1 پلسک — وضعیت فعلی این پروژه

هاست خریداری‌شده **پلسک** است:
`https://ir-plesk02.ihglobaldns.com:8443` روی آی‌پی `185.10.74.207`
با دامنهٔ **talkora.ir**.

> ⚠️ در پلسک، پوشهٔ ریشهٔ سایت **`httpdocs`** است، نه `public_html`.
> این رایج‌ترین اشتباه موقع مهاجرت از سی‌پنل است.

### گام ۰ — نیم‌سرور (اول این را انجام دهید)

بررسی شد: **`talkora.ir` هنوز به هیچ آی‌پی‌ای اشاره نمی‌کند.** یعنی
هرچقدر هم فایل آپلود کنید، سایت باز نمی‌شود. اول باید نیم‌سرورها ست شوند:

```
ns1.ihglobaldns.com     →  174.142.239.219
ns2.ihglobaldns.com     →  70.38.92.218
```

جایی که دامنه را خریده‌اید (ایرنیک یا نمایندگی فروش) این‌ها را وارد کنید.
اگر شرکت هاست نیم‌سرور دیگری به شما داده، **همان را بگذارید** — این‌ها
حدس از روی نام سرور شماست، نه چیزی که شرکت هاست رسماً اعلام کرده باشد.

بین چند دقیقه تا ۲۴ ساعت طول می‌کشد. برای بررسی:
```bash
nslookup talkora.ir 8.8.8.8
```
تا وقتی جواب نمی‌دهد، بقیهٔ گام‌ها را می‌توانید انجام دهید ولی سایت باز نمی‌شود.

### گام ۱ تا ۸

۱. وارد `https://ir-plesk02.ihglobaldns.com:8443` شوید
۲. **Websites & Domains** → `talkora.ir` → **File Manager**
۳. وارد **`httpdocs`** شوید
۴. فایل‌های پیش‌فرض پلسک را پاک کنید (`index.html` و صفحهٔ خوش‌آمد)
۵. فایل `talkora-site.zip` را **Upload** و بعد **Extract Files** کنید، سپس زیپ را پاک کنید
۶. **SSL/TLS Certificates** → «Install a free basic certificate provided by
   Let's Encrypt» → هم `talkora.ir` هم `www.talkora.ir` را تیک بزنید
۷. **Hosting & DNS** → **Hosting Settings** → تیک
   «Permanent SEO-safe 301 redirect from HTTP to HTTPS»
۸. باز کنید: `https://talkora.ir`  (پنل جداست — بخش T.1.a)

بعد از استخراج باید این ساختار را ببینید:
```
httpdocs/
├── index.html
├── .htaccess          ← مخفی؛ Settings → Show hidden files
├── robots.txt
├── sitemap.xml
└── fonts/
```
دکمه‌های «ورود» در سایت به `https://panel.talkora.ir/` می‌روند. تا وقتی
بخش T.1.a را انجام نداده‌اید، آن دکمه‌ها به صفحهٔ خطا می‌رسند.

### مشکلات خاص پلسک

| علامت | علت |
|---|---|
| خطای ۵۰۰ | پلسک روی «nginx only» است و `.htaccess` را نمی‌خواند. اسمش را به `.htaccess.bak` تغییر دهید؛ سایت بالا می‌آید، فقط بدون فشرده‌سازی |
| `.htaccess` را نمی‌بینم | File Manager → Settings → Show hidden files |
| هنوز صفحهٔ پلسک را می‌بینم | `index.html` پیش‌فرض پاک نشده، یا فایل‌ها در `httpdocs` نیستند |
| Let's Encrypt خطا می‌دهد | DNS هنوز اعمال نشده؛ صبر کنید تا `talkora.ir` باز شود، بعد دوباره بزنید |

## T.1.a پنل روی زیردامنه — `panel.talkora.ir`

این بخش ورود واقعی را راه می‌اندازد: کد یک‌بارمصرف از **sms.ir**، نشست
واقعی، و نقش کاربر از سرور. روی همین هاست اشتراکی پلسک اجرا می‌شود.

> نکته: در گفتگو `panel.talkora.com` نوشته شد، ولی دامنهٔ خریداری‌شده
> `talkora.ir` است. زیردامنهٔ درست **`panel.talkora.ir`** است. اگر
> `talkora.com` را هم بعداً خریدید، `PANEL_DOMAIN` را در `build-dist.py`
> عوض کنید و دوباره بسازید — هیچ جای دیگری دستی تغییر نمی‌خواهد.

### پیش‌نیازها

| نیاز | چرا |
|---|---|
| PHP ۸.۱+ | کد از `never`، تایپ‌های سخت و `match` استفاده می‌کند |
| اکستنشن `pdo_mysql` | اتصال به پایگاه داده |
| اکستنشن `curl` | ارسال پیامک به sms.ir. بدون این، کد هرگز فرستاده نمی‌شود |
| گواهی SSL روی زیردامنه | کوکی نشست پرچم `Secure` دارد؛ روی HTTP ست نمی‌شود |
| حساب sms.ir با خط خدماتی | بند P.4 — با خط تبلیغاتی، کد به بخشی از کاربران نمی‌رسد |

### گام‌ها

۱. **زیردامنه:** Websites & Domains → **Add Subdomain** →
   نام `panel`، دامنهٔ والد `talkora.ir`. مسیر پیش‌فرض پلسک را دست نزنید.

۲. **PHP:** روی زیردامنه → **PHP Settings** → نسخهٔ ۸.۱ یا بالاتر.
   در همان صفحه مطمئن شوید `pdo_mysql` و `curl` فعال‌اند.

۳. **پایگاه داده:** Databases → **Add Database**.
   بعد phpMyAdmin → تب **SQL** → محتویات
   `_نصب-آپلود-نکنید/پایگاه-داده.sql` را بچسبانید و **Go**.
   پنج جدول ساخته می‌شود: `app_user`، `otp_code`، `session_token`،
   `rate_limit`، `audit_log`.

   > پلسک به نام دیتابیس و کاربر پیشوند اضافه می‌کند. **همان چیزی را
   > در تنظیمات بنویسید که در فهرست Databases می‌بینید**، نه آنچه تایپ
   > کرده‌اید. این رایج‌ترین علت خطای «اتصال برقرار نشد» است.

۴. **آپلود:** محتویات `talkora-panel.zip` را در `httpdocs` زیردامنه
   بریزید. پوشهٔ `_نصب-آپلود-نکنید` را آپلود نکنید — روی سرور به آن
   نیازی نیست و فقط ساختار جدول‌ها را افشا می‌کند.

۵. **پیکربندی:** `api/config.sample.php` را به `api/config.php` تغییر نام
   دهید و پر کنید:

   ```php
   'db_name' => 'نامی که پلسک ساخت',
   'db_user' => 'کاربری که پلسک ساخت',
   'db_pass' => 'رمز گام ۳',
   'otp_pepper' => 'یک رشتهٔ تصادفی ۶۴ کاراکتری',   // openssl rand -hex 32
   'smsir_api_key' => 'کلید از پنل sms.ir',
   'smsir_template_id' => 12345,
   'sms_dry_run' => false,
   ```

   > **`otp_pepper` را از فایل نمونه کپی نکنید.** کدها با
   > `hash_hmac('sha256', phone.':'.code, pepper)` ذخیره می‌شوند و خود کد
   > هیچ‌جا نوشته نمی‌شود. اگر pepper قابل حدس باشد، هش‌ها هم قابل حدس‌اند.
   > اگر بعداً عوضش کنید، کدهای در جریان باطل می‌شوند — که مشکلی نیست،
   > کاربر دوباره درخواست می‌کند.

   امن‌تر: `config.php` را بیرون از `httpdocs` بگذارید، در
   `private/talkora-config.php`. کد اول همان‌جا را می‌گردد و اگر نبود
   سراغ `api/config.php` می‌رود.

۶. **قالب پیامک sms.ir:** پنل sms.ir → «ارسال وریفای» → افزودن قالب:

   ```
   کد ورود شما به تاکورا: #CODE#
   این کد تا ۲ دقیقه معتبر است.
   ```

   شناسهٔ عددی قالب را در `smsir_template_id` و نام پارامتر (`CODE`) را
   در `smsir_param_name` بگذارید. **نام پارامتر باید مو به مو با قالب
   یکی باشد**، وگرنه sms.ir قالب را رد می‌کند.

۷. **SSL:** SSL/TLS Certificates → Let's Encrypt برای `panel.talkora.ir`.

### آزمایش، به همین ترتیب

```
۱)  https://panel.talkora.ir/api/health.php
    انتظار:  {"ok":true, … "database":true,"sms":"configured"}

۲)  https://panel.talkora.ir/api/config.php
    انتظار:  ۴۰۴ یا ۴۰۳ یا صفحهٔ خالی — هرگز محتوای فایل

۳)  https://panel.talkora.ir
    نوار «نسخهٔ نمایشی» نباید دیده شود. شمارهٔ خودتان را بزنید.
```

اولین کسی که با نام آموزشگاه ثبت‌نام کند نقش **مدیر** می‌گیرد؛ کسی که
نام آموزشگاه را خالی بگذارد **زبان‌آموز** می‌شود.

### دو لایه محافظت از فایل‌های داخلی

`.htaccess` دسترسی به `_bootstrap.php`، `_sms.php` و `config.php` را
می‌بندد — ولی اگر پلسک روی حالت **nginx only** باشد `.htaccess` خوانده
نمی‌شود. برای همین هر فایل داخلی خودش هم این بررسی را دارد:

```php
if (realpath(__FILE__) === realpath((string)($_SERVER['SCRIPT_FILENAME'] ?? ''))) {
    http_response_code(404);
    exit;
}
```

یعنی فایل اگر مستقیم صدا زده شود ۴۰۴ می‌دهد و اگر با `require` بیاید
عادی کار می‌کند — مستقل از وب‌سرور. با این حال گام ۲ آزمایش را انجام
دهید؛ اگر رمزها را دیدید، فوراً عوضشان کنید.

### قواعد امنیتی که در کد اعمال شده (بند S.8)

| قاعده | مقدار |
|---|---|
| طول کد و اعتبار | ۵ رقم، ۲ دقیقه |
| ذخیره‌سازی | فقط HMAC-SHA256؛ خود کد هیچ‌جا نوشته نمی‌شود |
| سقف تلاش برای هر کد | ۵ بار، بعدش کد باطل می‌شود |
| سقف درخواست هر شماره | ۵ در ساعت |
| سقف درخواست هر IP | ۲۰ در ساعت |
| فاصلهٔ ارسال دوباره | ۶۰ ثانیه |
| پاسخ برای شمارهٔ موجود و ناموجود | یکسان، تا فهرست کاربران قابل استخراج نباشد |
| کوکی نشست | `httpOnly`، `Secure`، `SameSite=Lax`، توکن هش‌شده در دیتابیس |
| ناموفق‌بودن ارسال پیامک | کد فوراً باطل می‌شود تا کاربر با کدی که نرسیده گیر نکند |

### اشکال‌زدایی

| علامت | علت |
|---|---|
| نوار «نسخهٔ نمایشی» دیده می‌شود | `api/health.php` جواب نداده. مستقیم بازش کنید |
| `"ok":false` در health | اطلاعات دیتابیس در `config.php` غلط است |
| `"sms":"dry_run"` | `sms_dry_run` را `false` نکرده‌اید؛ کد فقط در لاگ می‌رود |
| `"sms":"missing"` | `smsir_api_key` خالی است |
| «ارسال پیامک ممکن نشد» | کلید غلط، اعتبار sms.ir تمام، یا `curl` خاموش. لاگ خطای PHP در پلسک علت دقیق را می‌نویسد |
| کد می‌رسد ولی «کد منقضی شده» | ساعت سرور با واقعیت جور نیست. از پشتیبانی بخواهید NTP را تنظیم کند |
| بعد از ورود بلافاصله بیرون می‌افتم | SSL فعال نیست، پس کوکی `Secure` ست نمی‌شود |

## T.1.b سایر هاست‌های اشتراکی (سی‌پنل یا دایرکت‌ادمین)

### گام به گام

**۱. دامنه را به هاست وصل کنید**
در پنل جایی که دامنه را خریده‌اید (ایرنیک یا فروشنده)، **نیم‌سرورها (Nameservers)** را
به آنچه شرکت هاست داده تغییر دهید. معمولاً چیزی شبیه:
```
ns1.your-host.ir
ns2.your-host.ir
```
اعمال شدنش بین چند دقیقه تا ۲۴ ساعت طول می‌کشد.

**۲. وارد File Manager شوید**
کنترل‌پنل → File Manager → پوشهٔ `public_html`
(در پلسک: `httpdocs`)

**۳. فایل‌های قبلی را پاک کنید**
اگر صفحهٔ پیش‌فرض شرکت هاست آنجاست (`index.html` یا `default.html`)، پاکش کنید.

**۴. محتویات `dist/site/` را آپلود کنید**

> ⚠️ خودِ پوشه را آپلود نکنید؛ **محتویاتش** را آپلود کنید.
> اگر پوشه را آپلود کنید، سایت روی `example.ir/site/` می‌افتد نه `example.ir/`.

ساده‌ترین راه: `talkora-site.zip` را در `public_html` آپلود کنید،
روی آن راست‌کلیک و **Extract** بزنید، بعد فایل زیپ را پاک کنید.

بعد از آپلود باید این‌ها را ببینید:
```
public_html/
├── index.html
├── .htaccess          ← مخفی است
├── robots.txt
├── sitemap.xml
└── fonts/
    ├── dana-bold.woff2
    ├── dana-light.woff2
    └── dana-regular.woff2
```

> فایل `.htaccess` **مخفی** است. در File Manager از تنظیمات،
> «Show Hidden Files» را روشن کنید وگرنه فکر می‌کنید آپلود نشده.

**۵. گواهی SSL را فعال کنید**
سی‌پنل → SSL/TLS Status → **Run AutoSSL**
دایرکت‌ادمین → SSL Certificates → Let's Encrypt

منتظر بمانید تا سبز شود. تا وقتی SSL نیامده، `.htaccess` شما را به `https` می‌فرستد
و مرورگر خطای گواهی می‌دهد — این طبیعی است، فقط چند دقیقه صبر کنید.

**۶. باز کنید**
```
سایت معرفی →  https://YOUR-DOMAIN
پنل        →  https://panel.YOUR-DOMAIN   (بستهٔ جدا، بخش T.1.a)
```

### اگر کار نکرد

| علامت | علت و راه حل |
|---|---|
| صفحهٔ سفید | `index.html` مستقیم در `public_html` نیست؛ احتمالاً داخل یک پوشهٔ اضافه است |
| فونت‌ها فارسی نیستند و بدشکل‌اند | پوشهٔ `fonts/` آپلود نشده، یا کنار `index.html` نیست |
| خطای ۵۰۰ | `.htaccess` با تنظیمات هاست جور نیست. موقتاً اسمش را به `.htaccess.bak` تغییر دهید؛ سایت بالا می‌آید، فقط بدون فشرده‌سازی و کش |
| حلقهٔ بی‌نهایت ریدایرکت | SSL هنوز فعال نشده. صبر کنید یا موقتاً بخش RewriteEngine را کامنت کنید |
| «Index of /» نشان می‌دهد | نام فایل باید دقیقاً `index.html` باشد، نه `Index.html` |
| تغییرات را نمی‌بینم | کش مرورگر. `Ctrl+Shift+R` بزنید |

## T.2 سرور مجازی (VPS) — وقتی بک‌اند هم می‌خواهید

اگر «سرور مجازی» گرفته‌اید (دسترسی root و SSH دارید):

```bash
# ۱) وصل شوید
ssh root@YOUR_SERVER_IP

# ۲) پروژه را بیاورید
apt-get update && apt-get install -y git
git clone YOUR_REPO_URL /opt/talkora && cd /opt/talkora

# ۳) سرور را آماده کنید — فایروال، SSH فقط با کلید، داکر، ساعت UTC
bash infra/bootstrap.sh

# ۴) تنظیمات
cp infra/.env.example infra/.env
nano infra/.env          # رمز پایگاه داده، کلید پیامک، کلید درگاه…

# ۵) بالا بیاورید
cd infra && docker compose up -d

# ۶) پایگاه داده
docker compose exec -T db psql -U talkora -d talkora < ../server/db/001_init.sql

# ۷) گواهی TLS
docker compose exec nginx certbot --nginx -d YOUR-DOMAIN

# ۸) سلامت
curl -s https://YOUR-DOMAIN/healthz
```

**دامنه:** رکورد `A` دامنه را به IP سرور بدهید. برای زیردامنه‌ها هم همین‌طور:
```
@      A   YOUR_SERVER_IP
app    A   YOUR_SERVER_IP
bbb    A   YOUR_BBB_SERVER_IP
```

> ⚠️ بند S.4: روی سرور ایران `npm install` معمولاً به رجیستری نمی‌رسد.
> **ایمیج را جای دیگری بسازید و push کنید**، روی سرور فقط `pull` کنید.
> وگرنه در مرحلهٔ بیلد گیر می‌کنید.

## T.3 سرویس ابری (لیارا، آروان)

اگر PaaS گرفته‌اید، فایل‌های `infra/` را لازم ندارید.

**لیارا — سایت استاتیک:**
```bash
npm i -g @liara/cli
liara login
cd dist && liara deploy --platform static --app YOUR-APP-NAME
```

**لیارا — بک‌اند:** یک اپ `docker`، یک دیتابیس `postgresql` و یک `redis` بسازید،
`DATABASE_URL` و `REDIS_URL` را از پنل بردارید و در متغیرهای محیطی اپ بگذارید.

**آروان:** ابر آروان → Container → ایمیج را از رجیستری بکشید، یا از
Object Storage برای میزبانی استاتیک استفاده کنید.

## T.4 کدام را بخرم؟

| اگر می‌خواهید | بخرید | تقریب هزینه |
|---|---|---|
| فقط سایت معرفی بالا باشد | هاست اشتراکی، ۱ گیگ | ارزان |
| سایت + نمونهٔ پنل برای نشان‌دادن به مشتری | همان هاست اشتراکی | همان |
| محصول واقعی با ثبت‌نام و پایگاه داده | سرور مجازی، ۴ هسته / ۸ گیگ | متوسط |
| کلاس آنلاین با BigBlueButton | یک سرور مجازی **جدا**، ۸ هسته / ۱۶ گیگ | بالاتر |

**نصیحت:** BBB را روی همان سرور اپ نگذارید. یک کلاس ویدیویی، CPU را می‌بلعد و
همان لحظه سایت و پنل کند می‌شوند.
